## Автоматическое тестирование

### Запуск unit-тестов

```bash
# Активируйте виртуальное окружение (если используется)
# Windows:
venv\Scripts\activate

# Linux/Mac:
source venv/bin/activate

# Запустите тесты
python test_regex.py
```

### Запуск интеграционных тестов

```bash
python test_integration.py
```

### Что проверяют тесты:

1. **test_regex.py** - проверяет функцию `build_regex`:
   - Простые линейные пути
   - Множественные переходы из одного состояния
   - Самопетли (переходы в себя)
   - Несколько меток, ведущих в одно состояние
   - Пустые состояния
   - Сложные структуры
   - Обнаружение циклов

2. **test_integration.py** - проверяет полный рабочий процесс:
   - Извлечение скриптов из текстов
   - Построение графа переходов
   - Генерацию регулярного выражения

## Ручное тестирование через GUI

### Шаг 1: Запуск программы

```bash
python gui_start.py
```

### Шаг 2: Создание нового объекта

1. В меню выберите: **Редактор семантических объектов → Создание объекта → Добавить текстовый поток**
2. Добавьте несколько текстовых потоков (ТП)

### Шаг 3: Добавление характеристик

1. В поле **Характеристики** введите характеристики в формате:
   ```
   Q1: описание характеристики 1
   Q2: описание характеристики 2
   Q3: описание характеристики 3
   ```
2. Нажмите **Сохранить характеристики**

### Шаг 4: Генерация регулярного выражения

1. Нажмите кнопку **Начать генерацию**
2. Дождитесь завершения процесса
3. Проверьте сгенерированное регулярное выражение в поле **Регулярное выражение**

### Шаг 5: Сохранение объекта

1. Введите имя объекта в поле **Имя объекта**
2. Нажмите **Сохранить объект**
3. Объект будет сохранен в папке `objects/` в формате JSON

### Шаг 6: Загрузка объекта

1. В меню выберите: **Редактор семантических объектов → Редактирование объекта → Выбрать объект**
2. Выберите сохраненный JSON файл
3. Проверьте, что данные загрузились корректно

## Тестирование функции build_regex

### Тест 1: Простой случай

```python
from regex import build_regex

transitions = {
    'S0': {'a': 'S1'},
    'S1': {'b': 'Z'},
    'Z': {}
}

result = build_regex('S0', transitions)
print(result)  # Ожидается: ab или (a)(b)
```

### Тест 2: Множественные переходы

```python
transitions = {
    'S0': {'a': 'S1', 'b': 'S2'},
    'S1': {'c': 'Z'},
    'S2': {'d': 'Z'},
    'Z': {}
}

result = build_regex('S0', transitions)
print(result)  # Ожидается выражение с альтернативами
```

### Тест 3: Самопетля

```python
transitions = {
    'S0': {'a': 'S0', 'b': 'S1'},
    'S1': {'c': 'Z'},
    'Z': {}
}

result = build_regex('S0', transitions)
print(result)  # Ожидается выражение с циклом (a)*
```

### Тест 4: Несколько меток в одно состояние

```python
transitions = {
    'S0': {'a': 'S1', 'b': 'S1', 'c': 'S1'},
    'S1': {'d': 'Z'},
    'Z': {}
}

result = build_regex('S0', transitions)
print(result)  # Ожидается: (a|b|c)d
```

## Проверка результатов

### Критерии успешного тестирования:

1. ✅ **Корректность синтаксиса**: Регулярное выражение должно быть валидным
2. ✅ **Обработка всех случаев**: Функция должна работать для:
   - Простых путей
   - Множественных переходов
   - Самопетель
   - Циклов
   - Пустых состояний
3. ✅ **Стандартный синтаксис**: Использование стандартных операторов регулярных выражений:
   - `|` для альтернатив
   - `*` для циклов (Kleene star)
   - `()` для группировки
4. ✅ **Отсутствие ошибок**: Программа не должна падать с ошибками
5. ✅ **Производительность**: Генерация должна завершаться за разумное время

### Что проверить в сгенерированном регулярном выражении:

1. **Структура**: Выражение должно отражать структуру графа переходов
2. **Полнота**: Все пути должны быть представлены в выражении
3. **Корректность**: Выражение должно быть синтаксически правильным
4. **Оптимизация**: Лишние скобки должны быть удалены

### Примеры ожидаемых результатов:

**Вход:**
```
S0 -> a -> S1 -> b -> Z
```

**Ожидаемый выход:**
```
ab
```
или
```
(a)(b)
```

**Вход:**
```
S0 -> a -> S1 -> c -> Z
S0 -> b -> S2 -> d -> Z
```

**Ожидаемый выход:**
```
(ac|bd)
```
или
```
((a)(c)|(b)(d))
```

**Вход:**
```
S0 -> a -> S0 (самопетля)
S0 -> b -> S1 -> c -> Z
```

**Ожидаемый выход:**
```
((a)*|b(c))
```
или подобное выражение с циклом

## Отладка

### Включение подробного вывода

Функция `build_regex` уже содержит print- statements для отладки. Они выводят:
- Обрабатываемые переходы
- Собранные выражения
- Обнаруженные циклы

### Проверка промежуточных результатов

1. Проверьте словарь переходов перед вызовом `build_regex`
2. Убедитесь, что начальное состояние 'S0' существует
3. Проверьте, что все состояния имеют корректные переходы

### Типичные проблемы:

1. **Пустое регулярное выражение**: Проверьте, что есть переходы из начального состояния
2. **Бесконечная рекурсия**: Убедитесь, что циклы обрабатываются корректно
3. **Некорректный синтаксис**: Проверьте, что используются стандартные операторы
